# Part 3: Triển khai Frontend SPA với Amazon S3 & CloudFront CDN

Trong phần trước, chúng ta đã xây dựng tầng Backend Django API chạy trên Amazon ECS Fargate và CSDL Amazon RDS MySQL. Ở Part 3 này, chúng ta sẽ chuyển sang tầng **Presentation Layer**: đóng gói ứng dụng **React SPA (Single Page Application)** và phân phối tới người dùng cuối với độ trễ tối thiểu (Low Latency) trên phạm vi toàn cầu.

Mô hình phân phối tĩnh (Static Website Hosting) bảo mật chuẩn AWS sẽ kết hợp các dịch vụ cốt lõi:

  </Card>

<Callout type="info" title="Ưu điểm vượt trội của mô hình OAC vs Static Website Hosting truyền thống">
  Trước đây AWS sử dụng **Origin Access Identity (OAI)** hoặc bật *Static Website Hosting* công khai S3 Bucket. Với **Origin Access Control (OAC)** mới, S3 Bucket vẫn giữ `Block All Public Access: Enabled`, hỗ trợ mã hóa Server-Side Encryption (SSE-KMS) và phòng chống tấn công DDoS trực tiếp vào S3 origin.
</Callout>

## Khởi tạo & Cấu hình 4 S3 Buckets Chuẩn Sản Xuất

Chúng ta cần tạo 4 S3 Buckets phân tách đúng chức năng nghiệp vụ của hệ thống NeonFoodMap:

| Tên Bucket (Ví dụ) | Mục đích lưu trữ | Versioning | Lifecycle Policy | Public Access |
| :--- | :--- | :--- | :--- | :--- |
| `neonfoodmap-frontend-dev` | Build artifacts của React SPA (HTML, JS, CSS) | Off | Không | Block All |
| `neonfoodmap-media-dev` | Hình ảnh địa điểm ẩm thực, banner | **Enabled** | Standard-IA sau 90 ngày | Block All |
| `neonfoodmap-audio-dev` | Băng ghi âm thuyết minh tự động (Audio Guides) | **Enabled** | Standard-IA sau 90 ngày | Block All |
| `neonfoodmap-logs-dev` | Access logs của CloudFront và S3 | Off | Expiration sau 365 ngày | Block All |

### Hướng dẫn Cấu hình Chi tiết

<Steps>

<Step>
### Bước 1: Khởi tạo Buckets & Bật Bucket Versioning
1. Đăng nhập **Amazon S3 Console** -> bấm **Create bucket**.
2. Nhập tên bucket duy nhất toàn cầu (ví dụ: `neonfoodmap-frontend-us-east-1`).
3. **Region:** Chọn cùng Region với VPC (`us-east-1` N. Virginia).
4. Giữ nguyên **Block All Public Access** ở trạng thái **Enabled**.
5. Chọn tab **Properties** -> Tại mục **Bucket Versioning**, chọn **Enable** đối với `media` và `audio` bucket để bảo vệ dữ liệu khỏi bị ghi đè hoặc xóa nhầm.
</Step>

<Step>
### Bước 2: Thiết lập Lifecycle Rule tối ưu chi phí lưu trữ
Dữ liệu hình ảnh và audio sau 90 ngày ít khi thay đổi sẽ tự động chuyển sang tầng lưu trữ **Standard-Infrequent Access (Standard-IA)** để tiết kiệm 40% chi phí.

1. Vào tab **Management** tại `media` bucket -> bấm **Create lifecycle rule**.
2. Đặt tên rule: `Move-to-IA-after-90d`.
3. Chọn **Apply to all objects in the bucket**.
4. Tích chọn **Transition current versions of objects between storage classes**.
5. Select storage class: **Standard-IA**, nhập **Days after creation**: `90`.
6. Bấm **Create rule**.
</Step>

</Steps>

## Cấu hình Amazon CloudFront Distribution & Origin Access Control (OAC)

CloudFront đóng vai trò là điểm tiếp nhận duy nhất (Single Point of Entry) cho người dùng cuối.

<Tabs items={['AWS Console', 'AWS CLI']}>

<Tab value="AWS Console">

<Steps>

<Step>
### Bước 1: Tạo OAC (Origin Access Control)
1. Mở **CloudFront Console** -> chọn **Origin access** bên menu trái.
2. Bấm **Create control setting**:
   - **Name:** `OAC-NeonFoodMap-S3`
   - **Signing behavior:** Sign requests (recommended)
   - **Origin type:** S3
3. Bấm **Create**.
</Step>

<Step>
### Bước 2: Khởi tạo CloudFront Distribution
1. Mở **Distributions** -> bấm **Create distribution**.
2. **Origin domain:** Chọn bucket `neonfoodmap-frontend-dev.s3.us-east-1.amazonaws.com`.
3. **Origin access:** Chọn **Origin access control settings (recommended)** -> chọn `OAC-NeonFoodMap-S3`.
4. **Default cache behavior:**
   - Viewer protocol policy: **Redirect HTTP to HTTPS**
   - Allowed HTTP methods: `GET, HEAD`
   - Cache key and origin requests: **CachingOptimized**
5. **Custom error responses (Dành cho React SPA Client-side Routing):**
   - Bấm **Create custom error response**.
   - HTTP error code: `403` & `404`
   - Customize error response: **Yes**
   - Response page path: `/index.html`
   - HTTP Response code: `200`
6. Bấm **Create distribution**.
</Step>

<Step>
### Bước 3: Cập nhật S3 Bucket Policy cho phép CloudFront OAC
Sau khi tạo Distribution, CloudFront cung cấp một câu mẫu Policy. Bạn copy dán vào tab **Permissions** của S3 Frontend Bucket:

```json
{
  "Version": "2012-10-17",
  "Statement": {
    "Sid": "AllowCloudFrontServicePrincipalReadOnly",
    "Effect": "Allow",
    "Principal": {
      "Service": "cloudfront.amazonaws.com"
    },
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::neonfoodmap-frontend-dev/*",
    "Condition": {
      "StringEquals": {
        "AWS:SourceArn": "arn:aws:cloudfront::123456789012:distribution/E1A2B3C4D5E6F7"
      }
    }
  }
}
```
</Step>

</Steps>

</Tab>

<Tab value="AWS CLI">

```bash
# 1. Tạo OAC
OAC_ID=$(aws cloudfront create-origin-access-control \
  --origin-access-control-config '{
    "Name": "OAC-S3-Frontend",
    "Description": "OAC for React SPA S3 Bucket",
    "SigningProtocol": "sigv4",
    "SigningBehavior": "always",
    "OriginAccessControlOriginType": "s3"
  }' --query 'OriginAccessControl.Id' --output text)

echo "Created OAC ID: $OAC_ID"

# 2. Sync build folder React lên S3 Bucket
aws s3 sync ./dist s3://neonfoodmap-frontend-dev/ --delete
```

</Tab>

</Tabs>

## Kiểm tra & Xác nhận Cấu hình (Verification)

Sau khi CloudFront Distribution chuyển sang trạng thái `Last modified: Enabled`:

1. Copy tên miền do AWS cấp có dạng: `https://d111111abcdef8.cloudfront.net`.
2. Dán vào trình duyệt web để kiểm tra việc tải trang chủ ứng dụng React SPA.
3. Thử nghiệm truy cập trực tiếp đường dẫn S3 Endpoint (ví dụ: `https://neonfoodmap-frontend-dev.s3.us-east-1.amazonaws.com/index.html`).
   - *Kết quả mong đợi:* Mã lỗi `403 Forbidden` (Đảm bảo người dùng không thể đi tắt qua S3 để bypass CDN).
