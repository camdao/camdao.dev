# Part 1: Khởi tạo VPC & Hạ tầng Mạng Chuẩn Production

Hạ tầng mạng (Networking Infrastructure) là xương sống của mọi hệ thống trên AWS. Một thiết kế VPC chuẩn mực giúp bảo vệ tài nguyên nội bộ, đảm bảo tính sẵn sàng cao (High Availability) và hỗ trợ kết nối Internet an toàn cho các ứng dụng chạy trong Private Subnets.

Trong bài hướng dẫn này, chúng ta sẽ khởi tạo **Virtual Private Cloud (VPC)** kết hợp tính năng **VPC and more** trên AWS Console để tự động sinh ra mô hình mạng Multi-AZ chuẩn hóa với 2 Public Subnets, 4 Private Subnets và 1 NAT Gateway.

## Bảng Quy hoạch Dải Mạng (IP Planning)

Dưới đây là bảng phân bổ địa chỉ IP chi tiết cho 6 Subnets trong VPC:

| Tên Subnet | Loại Phân vùng | Availability Zone | CIDR Block | Số IP khả dụng | Mục đích sử dụng |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `fcj-public-subnet-1` | **Public** | `us-east-1a` | `10.0.0.0/20` | 4,091 | Application Load Balancer (Node 1) & NAT Gateway |
| `fcj-public-subnet-2` | **Public** | `us-east-1b` | `10.0.16.0/20` | 4,091 | Application Load Balancer (Node 2) |
| `fcj-private-subnet-1` | **Private** | `us-east-1a` | `10.0.128.0/20` | 4,091 | Backend Container Tasks (ECS Fargate AZ-a) |
| `fcj-private-subnet-2` | **Private** | `us-east-1b` | `10.0.144.0/20` | 4,091 | Backend Container Tasks (ECS Fargate AZ-b) |
| `fcj-private-subnet-3` | **Private** | `us-east-1a` | `10.0.160.0/20` | 4,091 | Amazon RDS MySQL Cluster Node (AZ-a) |
| `fcj-private-subnet-4` | **Private** | `us-east-1b` | `10.0.176.0/20` | 4,091 | Amazon RDS MySQL Cluster Node (AZ-b) |

<Callout type="warn">
  **Tại sao số IP khả dụng là 4,091 thay vì 4,096 cho dải /20?**  
  AWS luôn dành riêng **5 địa chỉ IP** trong mỗi Subnet cho các mục đích quản trị mạng (Network Address, VPC Router, DNS Server, Future Use & Broadcast Address).
</Callout>

## Hướng dẫn Triển khai Từng bước

Thực hiện theo các bước thao tác trên **AWS Management Console (Giao diện web)** dưới đây:

<Steps>

<Step>
### Bước 1: Tạo VPC với tính năng "VPC and more"
1. Đăng nhập vào **AWS Management Console** và tìm kiếm dịch vụ **VPC**.
2. Tại menu **Your VPCs**, chọn **Create VPC**.
3. Chọn tùy chọn **VPC and more** để tự động cấu hình các thành phần liên quan.
4. Cấu hình thông số:
   - **Name tag auto-generation:** nhập `fcj-workshop` (hoặc `NeonFood`).
   - **IPv4 CIDR block:** `10.0.0.0/16`
   - **Number of Availability Zones (AZs):** `2`
   - **Number of public subnets:** `2`
   - **Number of private subnets:** `4`
   - **NAT gateways:** `In 1 AZ` (chọn 1 AZ để tối ưu chi phí cho lab)
   - **VPC Endpoints:** `None`
5. Xem lại sơ đồ preview hiển thị 6 Subnets, 1 IGW và 1 NAT Gateway.
6. Bấm **Create VPC** và chờ quá trình khởi tạo hoàn tất.
</Step>

<Step>
### Bước 2: Khởi tạo & Đổi tên Elastic IP (EIP) cho NAT Gateway
1. Trong menu bên trái, chọn **Elastic IPs**.
2. Bạn sẽ thấy 1 EIP vừa được tự động tạo kèm theo NAT Gateway.
3. Chọn EIP này, bấm nút **Edit** ở mục Name tag và cập nhật thành `EIP-NAT-AZ1a`.
4. Trường hợp chưa tạo EIP, chọn **Allocate Elastic IP address** -> Thêm Tag `Name=EIP-NAT-AZ1a` -> bấm **Allocate**.
</Step>

<Step>
### Bước 3: Cấu hình Bảng định tuyến (Route Table) cho Private Subnets
1. Truy cập mục **Route tables** từ thanh điều hướng bên trái.
2. Tìm và chọn Route Table liên kết với các Private Subnets trong AZ `us-east-1a`.
3. Chọn thẻ **Routes** -> bấm **Edit routes**.
4. Kiểm tra dòng định tuyến cho Internet Outbound:
   - **Destination:** `0.0.0.0/0`
   - **Target:** chọn **NAT Gateway** (chọn `NAT-Gateway-AZ1a`).
5. Bấm **Save changes** để lưu cấu hình.
</Step>

<Step>
### Bước 4: Bật tính năng Auto-assign Public IP cho Public Subnets
1. Chuyển sang mục **Subnets** trên thanh điều hướng.
2. Chọn `fcj-public-subnet-1` (hoặc `fcj-workshop-subnet-public1-us-east-1a`).
3. Bấm **Actions** ở góc trên phải -> chọn **Edit subnet settings**.
4. Tích chọn **Enable auto-assign public IPv4 address**.
5. Bấm **Save changes**.
6. Thực hiện tương tự cho `fcj-public-subnet-2` (Public Subnet tại AZ `us-east-1b`).
</Step>

</Steps>

## Kiểm tra & Xác nhận Cấu hình (Verification)

Sau khi hoàn thành các bước trên, hãy kiểm tra lại toàn bộ hạ tầng mạng bằng các lệnh AWS CLI:

```bash
# 1. Kiểm tra danh sách Subnets và dải IP CIDR
aws ec2 describe-subnets \
  --filters "Name=vpc-id,Values=$VPC_ID" \
  --query 'Subnets[*].{ID:SubnetId, CIDR:CidrBlock, AZ:AvailabilityZone, Name:Tags[?Key==`Name`].Value|[0]}' \
  --output table

# 2. Kiểm tra NAT Gateway đang ở trạng thái Available
aws ec2 describe-nat-gateways \
  --filter "Name=vpc-id,Values=$VPC_ID" \
  --query 'NatGateways[*].{ID:NatGatewayId, State:State, PublicIP:NatGatewayAddresses[0].PublicIp}'

# 3. Kiểm tra Route 0.0.0.0/0 trỏ tới NAT Gateway trên Private Route Table
aws ec2 describe-route-tables \
  --filters "Name=vpc-id,Values=$VPC_ID" \
  --query 'RouteTables[*].{ID:RouteTableId, Routes:Routes[?DestinationCidrBlock==`0.0.0.0/0`]}'
```

**Kết quả mong đợi:**  
- Danh sách trả về đủ 6 Subnets (2 Public, 4 Private) rải đều trên 2 AZs.
- NAT Gateway hiển thị `State: available` đi kèm 1 địa chỉ IP Public (EIP).
- Public Route Table chứa route `0.0.0.0/0 -> igw-xxxx`, Private Route Table chứa route `0.0.0.0/0 -> nat-xxxx`.

## Bài học Cốt lõi (Takeaways)

1. **VPC and more Wizard:** Giúp tự động tạo đồng bộ VPC, Subnets, Internet Gateway, NAT Gateway và Route Tables chỉ với 1 thao tác, giảm thiểu lỗi cấu hình thủ công.
2. **Outbound Internet Access for Private Subnets:** NAT Gateway cho phép các tài nguyên trong Private Subnet (như ECS Tasks hay EC2) cập nhật phần mềm, tải container images từ Internet nhưng ngăn chặn Internet chủ động truy cập ngược vào nội bộ.
3. **Cost Optimization:** Sử dụng **1 NAT Gateway** trong 1 AZ giúp giảm tối đa chi phí cho môi trường Dev/Testing (tiết kiệm ~32$/tháng cho mỗi NAT Gateway bớt đi).
