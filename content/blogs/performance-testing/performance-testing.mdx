Performance Testing là cách hệ thống phản dưới tác động của một khối lượng công việc nhất định. xét trên các khía cạnh tốc độ, độ ổn định, khả năng mở rộng, độ chịu tải.

### Functional Testing vs Performance Testing
Functional Testing: Kiểm tra nút này hoặc động đúng. bấm nút đăng nhập có đăng nhập không?

Performance Testing: Hệ thống làm được nhanh hay bị vấn đề gì khi có lượng người dùng vào hệ thống. 5 000 người cùng bấm thanh toán thì như nào?

### Các loại Performance Test

Có nhiều loại test cho mục đích khác nhau:

**Load Testing:** Mức tải  bình thường cho hệ thống, lượng người mà bạn dự đoán hệ thống sẽ chạy 

**Stress Testing:** Đẩy lượng truy cập cao lên vượt mức bình thường mục tiêu tìm điểm gãy hệ thống và khả năng phục hồi như nào

**Spike Testing:** kiểm thử đột biến, tăng tải lên đột ngột và cực nhanh rồi sau đó giảm nhanh khác với stress testing tăng dần.

**Soak Testing:** hệ thống chịu tải ở mứcc trung bình trong nhiều ngày và nhiều giờ để phát hiện các vấn đề phát hiện khi chạy theo thời gian.

### Các bước cơ bản thực hiện test

1. Xác định mục tiêu: Hệ thống chịu tải được như nào, hệ thống nghẽn ở đâu,..
2. Chọn đúng loại test: 

        Xác nhận tải bình thường → Load Test

        Tìm điểm gãy / capacity → Stress Test

        Sự kiện bùng nổ tức thời → Spike Test

        Ổn định dài hạn → Soak Test

3. Dựng workload
Mô tả cụ thể người dùng làm gì, tăng tải ra sao, kéo dài bao lâu.
4. Định nghĩa SLA
Viết rõ đậu rớt trước khi chạy. ví dụ tỉ lệ lỗi dưới 1%, 95% request dưới 2s.
5. Thiết lập môi trường giống production
Test trên môi trường khác production sẽ cho số liệu vô dụng, Cấu hình server dữ liệu, mạng càng giống thật càng tốt.
6. Đo baseline
Chạy một lần với tải nhẹ để lấy mốc chuẩn. đây là điểm để tham chiếu
7.  Chạy, quan sát, phân tích
Thực thi test, thu thập số liệu, so với SLA và baseline. Nếu rớt, tìm nguyên nhân (bottleneck)

### Thực hành

Mục tiêu: Đánh giá khả năng API /ping đáp ứng khi tải tăng đột ngột từ 50 lên 1.000 request/giây, duy trì trong 2 phút, và khả năng hồi phục khi tải trở về bình thường.

Loại test: Spike Test.

Kịch bản:
Giai đoạn	Thời gian	Tải mục tiêu
Tải nền	1 phút	50 RPS
Tăng tải đột ngột	1 giây	50 → 1.000 RPS
Duy trì tải cao	2 phút	1.000 RPS
Giảm tải đột ngột	1 giây	1.000 → 50 RPS
Theo dõi hồi phục	2 phút	50 RPS


Tiêu chí đậu/rớt:

Trong giai đoạn tăng tải và duy trì tải cao:
- p95 dưới 100 ms.
- p99 dưới 200 ms.
- Tỷ lệ request lỗi dưới 1%.
Trong toàn bộ bài test:
- Không có dropped_iterations.
- RPS thực tế theo sát tải mục tiêu.
Sau khi giảm tải:
- Trong vòng 1 phút, p95 trở về dưới 10 ms và tỷ lệ lỗi dưới 1%.
- Duy trì trạng thái này trong phút còn lại.

**Đo baseline**
```

import http from 'k6/http';
import { check } from 'k6';

export const options = {
  scenarios: {
    baseline: {
      executor: 'constant-arrival-rate',
      rate: 50,
      timeUnit: '1s',
      duration: '1m',
      preAllocatedVUs: 10,
      maxVUs: 50,
    },
  },

  summaryTrendStats: ['avg', 'med', 'p(95)', 'p(99)', 'max'],
};

export default function () {
  const res = http.get('http://localhost:8081/ping');

  check(res, {
    'status is 200': (r) => r.status === 200,
  });
}

```
```
import http from 'k6/http';
import { check } from 'k6';

export const options = {
  discardResponseBodies: true,

  scenarios: {
    stress: {
      executor: 'ramping-arrival-rate',
      startRate: 50,
      timeUnit: '1s',
      preAllocatedVUs: 100,
      maxVUs: 2000,

      stages: [
        { duration: '30s', target: 100 },
        { duration: '2m', target: 100 },

        { duration: '30s', target: 500 },
        { duration: '2m', target: 500 },

        { duration: '30s', target: 1000 },
        { duration: '2m', target: 1000 },

        { duration: '30s', target: 2000 },
        { duration: '2m', target: 2000 },

        // Quay về tải baseline để quan sát hồi phục
        { duration: '10s', target: 50 },
        { duration: '1m', target: 50 },

        { duration: '10s', target: 0 },
      ],
    },
  },

  thresholds: {
    http_req_duration: ['p(95)<100', 'p(99)<200'],
    http_req_failed: ['rate<0.01'],
    checks: ['rate==1'],
    dropped_iterations: ['count==0'],
  },

  summaryTrendStats: [
    'avg',
    'med',
    'p(90)',
    'p(95)',
    'p(99)',
    'max',
  ],
};

export default function () {
  const res = http.get('http://localhost:8081/ping', {
    timeout: '5s',
  });

  check(res, {
    'status is 200': (r) => r.status === 200,
  });
}
```

JVM chưa cho thấy dấu hiệu quá tải: heap cao nhất **435 MiB / 2,06 GiB**, CPU tiến trình cao nhất **17,2% theo dashboard**. Sau tải, heap và CPU giảm, latency trở về gần baseline.
